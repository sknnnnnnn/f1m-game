# F1M R54 — ชุดส่งมอบเพื่อยืนยันบนมือถือ

วันที่ 29 ตุลาคม 2026 · ฐาน R53 commit `a3169337a04aea38654ae1ff7c72ecfab39d06eb`

สถานะ: **โค้ด เว็บ และการจำลองผ่านการตรวจ / Release Candidate**
การรับรอง 60 FPS, จอดำ และภาพกลางคืน/ฝนบน Android ยัง **รอเครื่องจริง** ไม่ได้ถือว่าผ่านจากผล CPU หรือการนับ RAF

## สิ่งที่แก้

- แผนพิตรับหมายเลขรถครบ 1–22 และใช้ความเร็วสำหรับช่วงจอดของทุกทีม ไม่ข้ามไปใช้เกณฑ์ทางออกตั้งแต่ผ่านช่องจอดคันที่ 6
- ตรวจพิตพร้อมกัน 22 คันใน 11 ช่องร่วมทีม ทั้ง Bahrain, Shanghai, Suzuka เพื่อนร่วมทีมไม่ใช้ SERVICE/RELEASE ซ้อนกัน
- ลดข้อมูลแผนขับและรายงานกลยุทธ์คู่แข่งที่ไม่ได้ใช้บนหน้าจอ คงตำแหน่ง/ความเร็ว/ล้อ/ข้อมูลวาดรถครบ 22 คัน และข้อมูลละเอียดของสองคันที่ผู้เล่นคุม การเซฟ/วิเคราะห์ยังมีข้อมูลเต็ม
- ตัวเตรียม GPU instances ใช้ cache ต่อเฟรมและเก็บชุดที่เพิ่งซ่อนไว้ชั่วคราว ลดการสร้าง/ทิ้งบัฟเฟอร์ซ้ำเมื่อเปลี่ยนมุมกล้องหรือระดับรายละเอียด ภาพ สี การหมุนล้อ และความเสียหายยังอยู่
- โรงรถและฉากแข่งคืน drawing buffer ขนาดเต็มเมื่อซ่อนฉาก คืนขนาด/DPR เดิมก่อนวาดครั้งถัดไป ไม่เปลี่ยนคุณภาพของฉากที่กำลังแสดง
- ตัดการ interpolate ซ้ำรอบที่สอง ผลลัพธ์ตำแหน่งและ telemetry ตรงเดิมในชุดตรวจ 105 ตัวอย่าง
- Solver ไม่ clone สถานะก่อน substep เมื่อไม่ได้ใช้ wall-contact ผลฟิสิกส์และ records ยังตรง frozen solver
- หน้าโหลดเซฟรับได้ 32 MB ตามตัวโหลดของ worker แทน 8 MB และตรวจทีม/จำนวนรอบ/ช่วง Weekend หลังโหลดและเริ่มใหม่
- เก็บค่าภาพที่วาดจริงแยก Dry/Wet, Day/Night, Pack/Open/Pit ในรายงานเครื่องนี้ ไม่ส่งข้อมูลอัตโนมัติ CPU fallback ไม่ถูกนับเป็นหลักฐาน GPU ของ Android
- รีเพลย์เก็บคลิปเหตุการณ์ที่เกี่ยวข้องกับทีมของผู้เล่น ลดคลิปคู่แข่งที่เลือกดูไม่ได้ และแก้คำอธิบายมินิแมพจากยุคสามทีม

| Bahrain | 22 | 1 | 131.30 | 20 | 22 |
| Shanghai | 22 | 1 | 137.55 | 26 | 22 |
| Suzuka | 22 | 1 | 132.38 | 23 | 22 |

ไม่พบ race stop, controller rejection หรือ off-track ตามตัวตรวจในรอบแข่งทั้งสามสนาม การเปลี่ยนอันดับรวมการสวนคืนของคู่เดิม ไม่ใช่จำนวนคู่แซงที่ไม่ซ้ำ

พิตเป็น fixture เริ่มใกล้ช่องจอดแล้วใช้ฟิสิกส์ต่อจริง มีการให้หลักฐานช่างหลบพ้นรถจากสคริปต์ ไม่ใช่หลักฐานว่าภาพช่างพร้อมกัน 22 คันบน Android ถูกตรวจแล้ว พิตพร้อมกันจบที่ประมาณ 85.0 / 84.9 / 89.4 วินาทีจำลอง ไม่พบ SERVICE/RELEASE ซ้อนช่องร่วมทีม

- Regression เดิม 67 คู่ test/สนามผ่านในการรัน `node tests/run-engine.mjs` ครั้งเดียว (exit 0)
- Full transport ที่กริด 227,251 → 125,305 bytes ใน fixture (ลดประมาณ 44.9%)
- CPU เตรียม instances 2,200 ชิ้นเร็วขึ้นประมาณ 2.9 เท่าใน fixture หนึ่งครั้ง ผล buffer ตรงเดิม ไม่ใช่ผล FPS
- Frozen/source/model ที่ตรวจตรึงไว้ยังตรงเดิม การเปลี่ยน solver มีผลคำนวณตรงเดิม
- Browser UI: เลือก Cadillac, เลือก Perez/Bottas, ส่งบุกให้ Bottas และเห็นการตอบรับจริง แผงเลือกทีมล็อก Cadillac
- เบราว์เซอร์ทดสอบปิด WebGL ใช้ CPU fallback และหยุดเพราะเฟรมเกิน guard 2 วินาที จึงไม่ยืนยัน FPS, ภาพ instances บน GPU หรือจอดำของ Android

หลักฐานรายละเอียด: `ACCEPTANCE.json`, `UNIT.json`, `INSTANCES.json`, `CORE_PARITY.json`, `SOLVER.json`, `LAP_*.json`, `MULTIPIT_*.json`, `RENDERED_CREW_BUFFERS.json`, `TEAM_UI.jpg`

## เปิดและตรวจซ้ำ

Node 22+:

```sh
npm ci
npm run build
npm run preview
npm run test:release54
npm test
```

`npm run test:acceptance54` รันสนามละหนึ่งรอบและ fixture พิตแยกต่างหาก ใช้เวลามากกว่าชุด unit

บน Android เปิด R54 เล่นตามปกติ ระบบสะสมค่าภาพที่วาดจริงเอง จากนั้นเข้า ตั้งค่า → **บันทึกผลทดสอบเครื่องนี้** เพื่อดาวน์โหลด JSON `release54.performance` แยกสภาพแวดล้อมไว้ให้แล้ว ไม่มีการส่งออกไปที่อื่นอัตโนมัติ

ยังไม่ปิดการรับรองส่งมอบบนมือถือจนกว่าจะมีหลักฐานเฟรมเรตและอาการจอดำจากเครื่องจริง
