## แบบที่นำมาใช้

ผู้ใช้กำหนด Loading, หน้าหลัก เริ่ม/ตั้งค่า/ออก, เข้า Garage/Pit พร้อมช่าง และมี Practice/Qualifying/Race พร้อมเลือกแนว Garage 3D, Quick Race + Race Weekend และ cinematic transitions ขนาด/ตำแหน่งและรายละเอียดกล้องจากคำตอบแชทต้นทางใช้เป็นแนวทาง ไม่อ้างว่าทุกพิกัดเป็นคำสั่งผู้ใช้โดยตรง

Flow ที่ทำ: หน้าเริ่ม → โหลดโรงรถ → โรงรถ 3D → เลือกโหมด → เลือกสนาม → ตั้งเซสชัน → เตรียมรถ → โหลดสนาม → เซสชันจริง → ผล → กลับโรงรถ/ช่วงถัดไป

## สิ่งที่ใช้งานได้

- เริ่ม/ตั้งค่า/ออก แยกจากหน้าแข่ง ปุ่ม PLAY/GARAGE/ตั้งค่า/ออกอยู่ฝั่งซ้ายโรงรถ จอแนวตั้งวางปุ่มด้านล่าง ฉากรถอยู่ด้านบน
- โรงรถสามมิติใช้ car163 เดิม ช่างหกคนใช้ CrewBatch เดิม มีวงจรตรวจล้อ ถอยดูรถ และเดินในทางเดิน กล้องเปลี่ยนตามหน้า มีข้ามและ reduced-motion
- Quick Race เลือก Race/Practice/Qualifying แยกได้; Race Weekend เริ่ม Practice2 → Qualifying2 → Race ใช้เวลาควอลิฟายจริง ไม่สร้างเวลาทดแทนให้รถที่ไม่มีเวลา
- เลือกสนามจาก catalog เดิมทั้ง5สนาม (Canal/Ridge เป็นสนามสมมติ), ทีม3ทีม, จำนวนรอบ1–20จากตัวเลือก, อากาศ และ presetรถ ส่งเข้าระบบจริง
- Weekend เก็บรอบเรซที่เลือกผ่านการเปลี่ยนช่วงและเซฟ/โหลด โดยใช้ metadata เพิ่มเติมที่เข้ากันได้กับ save เดิม
- ตั้งค่าเสียง/ภาพก่อนสร้าง renderer ได้ แยกเซฟและอัปเดตออกอีกหน้า เตรียมระบบเซฟได้โดยยังอยู่เมนู
- หน้าแข่งมี โรงรถ/คุมทีม/ยาง–พิต/อันดับ และแถบเลือกนักขับ เริ่ม–พัก กล้อง และ BOX ปุ่มกลับโรงรถพักการแข่งขันไว้
- ปุ่มออกพักเกมแล้วแสดงหน้าปิดท้าย เว็บไม่บังคับปิดแท็บ
- อัปเดต cache แยกตาม path เพื่อให้ preview ไม่ล้าง cache ของเกมคนละ scope

## ผลตรวจ

67 engine jobs, entry/session tests3สนาม, unitเดินช่างด้วย CrewBatch จริง, build และ PWA/service-worker ผ่าน Leg length error สูงสุดประมาณ2.78e-16 ขณะ sample ท่าเดินครบ60วินาที

ตรวจด้วย Cloud Browser จริงทั้ง desktop และ iframe390×780 CSSpx: หน้าเริ่ม/โรงรถ/เลือกโหมด/สนาม/ตั้งทีม/รอบ/เตรียมรถ/โหลดสนาม; Quick Race Shanghai OCEAN1รอบถึงหน้าแข่งเลือกMALIและLAP1/1จริง; Weekend Suzukaคงค่าข้าม reload และเข้าเซสชัน2รอบ รถวิ่งจริงเกิน1นาทีจำลอง; กลับโรงรถพักเรซ; เปิดคุมทีมจากปุ่มตรง; คุณภาพภาพก่อน initialise; เตรียมเซฟก่อนโหลดโรงรถแล้วยังเข้าโรงรถได้

ทดสอบเซฟ/โหลดและเดินช่วงถัดไปด้วย Node; ไม่อ้างว่าจบ Weekend ทั้งรายการในเบราว์เซอร์ Cloud ใช้ CPU fallback จึงมีภาพหยาบ/FPSต่ำ และพบ guardพักเมื่อเฟรมขาดช่วงใน Quick Race ชุดหนึ่ง ไม่ใช่การวัด Android GPU

## ขอบเขตตัวทดลอง

ยังไม่ได้ทดสอบ Androidจริง, การแตะบนเครื่องจริง, ฟังเสียง, หรือ WebGLบนGPUจริง งานซ่อมระหว่างเรซใช้ระบบพิตเดิม ฉากช่างหน้าเมนูเป็นการตรวจเตรียมรถ ไม่ได้จำลองผลซ่อมฟิสิกส์ผ่านภาพเคลื่อนไหว

เมื่อเลือกสนามคนละสนาม ตัวเว็บโหลดใหม่ เก็บค่าที่เลือกและคืนหน้าเตรียมรถ ให้กดลงสนามอีกครั้ง ไม่มีการเปลี่ยนตำแหน่งรถแข่งเพื่อสร้างฉากเมนู

เกมลิงก์หลักยังเป็น R48; ตัวทดลองอยู่ใต้ /preview49/ ซอร์ส AI, solver, vehicle physics และโมเดลเดิมไม่เปลี่ยน
