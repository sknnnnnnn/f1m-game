# F1M — F1 25 driving calibration

รุ่น `ba525293537c4435` · ฐาน `7cfce508201fcfd0` · 27 ตุลาคม 2026

## เกณฑ์อ้างอิงและขอบเขต

ใช้ median minimum/apex speed รายโค้งจากหลายผู้เล่นของ F1 25 ตามไฟล์ที่ผู้ใช้ส่ง และตรวจตารางต้นทางของ Driver Dojo เพิ่มเติม ไม่ใช่ telemetry F1 จริงหรือรอบของ Max Verstappen ไม่อ้างว่าใช้ source code หรือ physics ของ EA

EA อธิบายการพัฒนา handling จาก feedback ของผู้เล่นและ sim racers และอธิบายผลของ downforce, transmission, brake balance และยางต่อการขับ ข้อมูลเหล่านี้ใช้เป็นหลักการ ส่วนสูตรและตัวควบคุมด้านล่างเป็นงานของ F1M

## สิ่งที่เปลี่ยน

1. สร้างถนน Bahrain/Suzuka ใหม่จากพิกัดแผนที่ telemetry ที่ปรับแนวและขนาดเข้ากับโลกเดิม เก็บ main/pit corridor และระดับความสูงเดิม โดยมีถนนเดียวกันสำหรับภาพกับฟิสิกส์ เป็น reconstruction โดยประมาณ ไม่ใช่ LiDAR
2. แก้ Shanghai T14 จากโค้ง schematic ที่บางจุดมีรัศมีประมาณ 6–7 เมตร ต่ำกว่าครึ่งความกว้างถนน 7.7 เมตร เป็น hairpin ต่อเนื่องรัศมีต่ำสุดประมาณ 19.6 เมตรในช่วงที่ตรวจ พร้อมสร้างไลน์ขับใหม่
3. ใช้ spatial racing path และ minimum-curvature line ทั้งสามสนาม ให้เข้า–apex–ออกโค้งต่อเนื่องบนพิกัดถนนจริง พร้อมไลน์แซง/ตาม/หลบและข้อจำกัดพื้นที่ของคู่แข่ง
4. ล็อกแผนไลน์เข้าโค้งระหว่างเบรกหนักจนผ่าน apex เพื่อไม่เปลี่ยนใจข้ามฝั่งถนนกลาง hairpin; recovery และ pit ยังมีสิทธิ์เหนือแผนนี้
5. เพิ่มตัวคุมมุมลื่นยางหน้า: คลายพวงมาลัยเมื่อคำสั่งเลี้ยวเกินช่วงแรงเกาะที่ใช้ได้ แทนการถือพวงมาลัยเต็มแล้วไถลออก โดยไม่แก้พิกัด ความเร็ว หรือ core physics
6. แก้ braking envelope ให้ประเมิน downforce ที่ความเร็วปลายการคำนวณจริงในแต่ละช่วง ด้วย fixed-point iteration เดิมใช้ความเร็ว cap บนทางตรงประเมินกำลังเบรก แล้วค่อยลดความเร็ว ทำให้ประเมินแรงกดอากาศสูงเกินจริงก่อนโค้งช้า
7. เผื่อ downforce สำหรับ wake ที่อาจเปลี่ยนในอายุแผน 100 ms และสงวนแรงเกาะเมื่ออยู่ใกล้คู่แข่ง
8. แก้แผน recovery จากขอบถนนให้เริ่มจากตำแหน่งที่วัดจริงและหันกลับเข้าด้านใน ไม่สืบทอดความเร็วด้านข้างของแผนแซงเก่า; ไม่ย้ายรถหรือปิด collision guard
9. ปรับ thermal capacity/heat exchange ผ่าน vehicle preset เดิม และปรับ wear ของ compounds ให้การเสื่อมไม่ทำให้แรงเกาะตกหนักภายในสองรอบ คงสมการพลังงาน/ความร้อน/การสึกและผลฝนเดิม
10. ปรับความต่อเนื่องของคันเร่งและใช้แรงต้านอากาศชะลอความเร็วส่วนเกินเล็กน้อยเมื่อแผนยังถึงได้ การเบรกจริง/ฉุกเฉิน/รถขวางยังตอบสนองทันที

ยังคง frozen solver/controller/C0 และโมเดลรถเดิม ไม่มีการลดกราฟิก DPR เงา หรือระยะมอง ไม่มีการบังคับรถให้มีความเร็วตรงตัวเลขอ้างอิง

npm test (28 jobs รวม regression ของ entry braking / steering slip / edge connector), build และ PWA static/service-worker tests ผ่าน รวม core checksum และ serial/worker parity เดิม ตรวจ geometry สะพาน Suzuka, pit cycles ทั้งสามสนาม, 1,980 transition plans และการเบรกคันหน้าขณะออกตัวเพิ่มเติม

Warm planning benchmark หลังแก้ braking envelope: ประมาณ 0.528 ms/plan ต่อ 1,000 แผนใน Node เทียบรุ่นก่อนประมาณ 0.401 ms/plan เป็นการเพิ่มงานคำนวณเพื่อความถูกต้อง ไม่อ้างว่าเพิ่ม Android FPS

## สิ่งที่ยังไม่ตรงทั้งหมด

- Shanghai T4/T13 ยังมีช่วงนิยาม apex กับจุดเร่งออกต่างกันอย่างเห็นได้ชัด และ T16 ยังช้ากว่าฐาน จึงไม่ลดความเร็วหรือย้าย marker เพื่อทำให้สถิติดูตรง
- ชุดข้อมูลเป็น median ผู้เล่นหลายคน มีความต่างของ setup, fuel, tyre state และฝีมือ ค่า 46/49 ภายใน ±20% ไม่ใช่การรับรองว่า handling เหมือน F1 25 ทุกสถานการณ์
- ยังไม่ได้วัด GPU/FPS หรือให้คนขับบน Android เครื่องจริงของผู้ใช้ รุ่นนี้ยืนยันจากฟิสิกส์ใน Node, โครงฉาก, build และ asset checks; ไม่รายงาน browser full-race หรือ Android QA ว่าผ่าน
